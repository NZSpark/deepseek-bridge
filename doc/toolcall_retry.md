# 坏结构重发 · 设计（toolcall_retry.md）

> 参考实现：GLMBridge `glm_web/completion/malformed.py`。
> 本文把它的「检测 + 补救」思路移植到 DeepseekBridge，并结合本项目独有的
> **DSML 结构化形态**（`toolcalls.py`）与**重试阶梯**（`chat_io.send_chat`）做适配。
> 目标：网页端把 tool_call 生成坏了时，**就地重发一次**，而不是把坏文本当回答交回客户端。

---

## 1. 问题

DeepSeek 网页版没有原生 function calling，本项目靠「提示词注入 + 结构化解析」模拟
（见 `doc/prompt_design.md`）。但网页端**不稳定**：

- 围栏只开不闭（生成被截断）；
- 围栏正文为空（内容被 DOM 吃掉，只剩语言标记）；
- JSON 被截断 / 语法错（尾逗号、单引号、断在半截键名）；
- 裸 `tool_call` 标记后面什么都没有；
- 偶尔退回**原生 DSML 工具 DSL**（`<｜｜DSML｜｜ calls>`），解析层能救一部分，救不了的也是坏。

这些坏结构如果原样交给客户端：

- 客户端（Codex / Claude Code 等）拿到一段**看起来像回答、其实是废文本**的内容，
  既不会执行工具，也不会重试——任务在这一轮**静默死掉**；
- 用户看到的是「模型什么都没做」，根因被埋掉。

所以需要一层**独立于上游超时重试**的补救：识别「这一轮声称要调用工具，但没产出任何
可落地的调用」，**发一句纯提示词让模型就地重发一次**。

---

## 2. 与上游重试阶梯的区别（不要混）

`chat_io.send_chat` 已经有一套**上游重试阶梯**（首级用现有会话 → 恢复同一会话 →
换新会话播种）。那套处理的是「**网页没给出回复**」（超时 / 页面失效 / 会话到顶）。

本文的「坏结构重发」处理的是「**网页给了回复，但回复里的调用是坏的**」。两者正交：

| | 上游重试阶梯 | 坏结构重发（本文） |
| --- | --- | --- |
| 触发 | 无回复 / 超时 / 页面失效 | 有回复，但 tool_call 结构损坏 |
| 手段 | 恢复页面 / 换会话播种 | 同一会话里**再发一句提示词** |
| 位置 | `chat_io.send_chat` 内部 | 拿到 `reply_content` **之后**、解析之前 |
| 上限 | `MAX_UPSTREAM_RETRIES` | `MALFORMED_RETRIES`（独立计数） |

**关键**：坏结构重发**不换会话、不重放历史**——上下文没丢，只是这一轮文本坏了，
在同一会话里补一句话让模型重来即可。

---

## 3. 判据

**出现了 `tool_call` 标记，但没有任何一段包裹的内容是合法调用 → 判为损坏，需要重发。**

### 3.1 合法（一段正文）

一段正文「合法」当且仅当：

1. 能被 `json.loads` 解析成 **JSON 对象**；
2. 含**非空字符串** `name`；
3. `arguments` 是**对象**（`dict`）。

口径必须**与解析层一致**（含全角归一，见 `toolcalls.py` 与 `_loads_lenient`）：
网页端会把 JSON 里的 ASCII 引号/冒号/逗号渲染成全角，解析层有全角归一兜底。
若判据不做同一张映射，会出现「解析层能读、判据判坏」——真实事故：一轮里一个好的
（全角渲染）+ 一个坏的，判据把好的也判坏，整轮判成「没有可用调用」而重发，好的
调用**永不被执行**。

### 3.2 损坏（一段正文）

凡是读不出上述对象的都算损坏：

- 围栏正文为空；
- JSON 被截断（括号不闭合 / 断在半截键名上）；
- JSON 语法错（括号平衡但非法，如 `{bad}`、尾逗号、单引号）；
- 裸 `tool_call` 标记后面什么都没有。

### 3.3 刻意不看的东西

- **普通 `python` / `bash` / `json` 等其它语言围栏**：正常回答里出现代码块是常态，
  把它们判成损坏会导致对每个含代码的回答都重发一次。
- **工具名是否在 `valid_names` 里**：那是解析层（带 `declared`）的事；判据只看结构。
  名字对不上不算「坏结构」，是「调用了不存在的工具」，交给上层过滤。

### 3.4 围栏未闭合优先（独立结构信号）

即使某段正文的 JSON **恰好合法**（例如参数为空、恰好在某键值后截断成平衡括号），
只要存在一个 ` ```tool_call ` 开围栏**没有对应闭合**，整轮就判坏、必须重发。

理由：形状合法不代表调用完整。客户端拿到一个参数残缺但形状合法的调用，会执行出
错误结果，比直接重发更坏。围栏闭合是独立于 JSON 语法的结构信号——开围栏出现就
必然要有一个闭合。

**开围栏匹配口径**：语言标记后的分隔**不能要求必须换行**。网页渲染可能把内容挤到
同一行（` ```tool_call{"name": ...} `），也可能用 CRLF。只要求「`tool_call` 之后不是
标识符字符」（`(?![0-9A-Za-z_])`），与裸标记口径一致。

只判 `tool_call` 语言围栏；普通 `python` / `bash` 等代码围栏不参与截断判定。

### 3.5 逐段 vs 整轮

一轮回复可能同时有**多个调用，好坏混杂**。提供两个层次的判据：

- **整轮**（`has_no_usable_call`）：**所有**段都不可用才判坏、才重发。只要有一段能
  落地，就不重发——好的交给解析层执行，坏的由模型在下一轮看到反馈后自行补（部分成功）。
  这是**重发决策**用的版本。
- **逐段**（`has_malformed_tool_call`）：**任一**段非法即 `True`。用于「这段调用本身
  是否可用」的判断（例如单段校验、日志）。

用整轮版做重发决策，避免「好坏混杂时误杀已能执行的调用」。

## 4. 补救

发一句**纯提示词**（不加 system 构造、不加工具说明、不加历史），让模型就地重发一次调用：

````
调用失败，重新调用。需要调用工具时，只输出一个如下格式的代码块（arguments 必须是合法 JSON）：
```tool_call
{"name": "工具名", "arguments": {参数对象}}
```
一次只发一条指令，不要有多余解释的话或标记、标号。代码块要用```完成闭合。
````

要点：

- **纯提示词**：不重发整个 prompt，不重放历史——上下文还在，只需一句纠偏。
- **正面格式 + 闭合要求**：只给正确形状，**不写出原生 DSML 标记的字面形状**（见 P0-N：
  「禁止输出 X」等于把 X 示范一遍，「禁止」会变成「诱导」）。
- **有限次**：`MALFORMED_RETRIES`（默认 2），失败如实抛出而不是静默吞掉。

## 5. 落地位置

判据（`has_no_usable_call` / `has_malformed_tool_call` / `has_unclosed_tool_fence`）
放**解析层旁边**（`deepseek_web/toolcalls.py` 或新文件 `malformed.py`），与
`parse_tool_calls` 共用全角归一口径。

重发循环放在**拿到回复、解析之前**，即 `server.py` / `streaming.py` / `responses.py`
三处 `parse_tool_calls(...)` 调用点之前的公共路径。推荐抽一个
`complete_with_toolcall_retry(driver, prompt, seeded_prompt, key, wants_tools, ...)`：

```
async def complete_with_toolcall_retry(...) -> tuple[str, list[dict]]:
    result = await driver.send_chat(prompt, seeded_prompt=..., key=..., images=...)
    text, blocks = result
    if not wants_tools:
        return result
    retries = 0
    while has_no_usable_call(text) and retries < config.MALFORMED_RETRIES:
        retries += 1
        print(f"[重发] 检测到 tool_call 坏结构，第 {retries} 次重发…")
        # 重试轮不带 images，避免同一批图贴两次
        text, blocks = await driver.send_chat(RETRY_PROMPT, key=...)
    if has_no_usable_call(text):
        raise MalformedToolCallError(...)   # 或退回把原文本当回答 + 记 warning
    return text, blocks
```

**只在 `wants_tools`（声明了 tools 且 `tool_choice != none`）时启用**——纯文本请求
出现 `tool_call` 字样是正常讨论，不能重发。

### 5.1 重试轮的两条硬约束

1. **不带 images**：`RETRY_PROMPT` 是纯文本补话，同一批图若再粘一次会在会话里出现两份，
   干扰模型。首轮已经粘过，重试轮省略。
2. **不触发上游重试阶梯的「换新会话」**：重试轮仍是同一 `key`、同一会话；若 `send_chat`
   内部因超时走了恢复，那是它自己的事，与坏结构重发互不影响。

## 6. 与 DSML 解析的关系

`toolcalls.py` 已经能救大部分 DSML 结构化形态（`_parse_dsml_invokes` 等）。
**判据只看 ` ```tool_call ` 围栏与裸标记**，不把 DSML 标签当「损坏」——因为：

- DSML 是模型退回原生 DSL 的**另一种合法表达**，解析层能读就不是坏结构；
- 判据若把 DSML 也算进去，会与解析层的救活能力打架（解析层能读、判据判坏）。

只有当**整轮既没有可用 `tool_call` 段、也没有解析层能救的 DSML 调用**时，
`has_no_usable_call` 才应为 `True`。实现上可在判据里复用解析层：

```
if parse_tool_calls(text, valid_names):   # 解析层能救出任何调用
    return False                          # 不算坏，交给执行
```

即「**解析层救得活 → 不重发**」是最高优先级的短路。

## 7. 测试（能变红）

| 用例 | 期望 | 变红条件 |
| --- | --- | --- |
| 围栏正文为空 | `has_no_usable_call=True` | 空 body 判成合法 |
| JSON 截断（缺 `}`） | `True` | 截断判成合法 |
| 尾逗号 / 单引号 | `True` | 宽松解析放过 |
| 裸 `tool_call` + 空 | `True` | 裸标记未识别 |
| 围栏未闭合但 JSON 恰好合法 | `True` | 只看 JSON 不看闭合 |
| 一轮内「好的 + 坏的」混杂 | `has_no_usable_call=False` | 整轮判据误杀好调用 |
| 全角渲染的好调用 | `False`（不误判） | 判据不做全角归一 |
| 普通 `python` 代码块 | `False` | 其它语言围栏被当损坏 |
| DSML 可解析调用 | `False` | 判据不短路解析层 |
| 重发后仍坏 | 抛出，不静默 | 静默吞掉 |

---

## 8. 配置

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `MALFORMED_RETRIES` | `2` | 坏结构重发次数上限；0 = 关闭 |
| （复用）`RETRY_BACKOFF_S` | `1.0` | 重发前退避，避免连发 |

关闭后行为回到「坏文本原样交给客户端」——仅用于排查，不建议常态关闭。

---

## 9. 不做（WONTFIX）

- **无限重发**：会烧额度且掩盖真故障；有限次后如实报错。
- **重发时换会话 / 重放历史**：上下文没丢，换会话是另一套阶梯（`send_chat`）的事。
- **把 `tool_call` 字样出现在正文里当损坏**：正常讨论会被误伤；只在行首/空白后且
  后面跟着「要么 JSON、要么什么都没有」时才算标记（裸标记口径）。
