# Bridge 聊天命令（`/bridge ...`）

> 实现状态（2026-10-11）：以下命令**已全部实现**。识别与执行在
> `deepseek_web/bridge_commands.py`，Chat Completions 与 Responses 两条协议路径共用
> 同一个入口；设计约定参考姊妹项目 ChatGPTBridge 的 `doc/bridge_command.md`。
> 命令由本地桥接层直接应答、**不发给 DeepSeek 网页版**，因此页面失效、浏览器还没
> 初始化时它们仍然可用（普通请求照旧 503）。

## 1. 命令清单

| 命令 | 作用 | 风险 |
| --- | --- | --- |
| `/bridge help [session]` | 列出命令 / 分主题帮助 | 只读 |
| `/bridge status` | 桥接、浏览器与当前会话桶状态摘要 | 只读 |
| `/bridge models` | 本桥对外公布的模型名（与 `GET /v1/models` 同源） | 只读 |
| `/bridge session [status]` | 当前桶的会话状态摘要 | 只读 |
| `/bridge session reset` | 下一轮开新网页会话并播种完整历史 | 改状态 |
| `/bridge session reseed` | 下一轮把完整历史再播种一遍（一次性标记，落盘） | 改状态 |
| `/bridge session link <URL> [--seed]` | 把当前桶绑定到指定网页会话 | 改状态 |
| `/bridge session unlink` | 解除当前桶的会话绑定 | 改状态 |

`link` 接受完整地址 `https://chat.deepseek.com/a/chat/s/<会话 ID>`，也接受**裸会话 ID**
（会自动补全）。地址校验：`https` + 主机在 `LINK_ALLOWED_HOSTS` 里 + 路径形如
`/a/chat/s/<会话 ID>`；校验失败时明确回绝，绝不「猜一个」目标导航过去。

## 2. 识别规则

* **精确匹配**：只有「整条消息就是那一行」才算命令。混在正文里、多行文本里、引用块或
  代码块里出现的命令字样一律当成普通提问交给模型。
* **只看最后一条消息**，并且它必须是 `user`。工具循环的后续请求带着同一批历史
  （末尾是 `tool` 结果）时，旧命令**不会**被重新执行。
* 只有 `/bridge` 命名空间被保留；其它任何 `/` 开头的文本照旧发给网页版。
* `/bridge` 命名空间内**语法已匹配但参数不合法**的写法会回一条用法提示（带命令清单），
  而不是悄悄把它发给模型。

## 3. 作用范围与语义

* **只作用于当前会话桶**：命令没有「指定别的桶」的参数。桶由 `X-DeepSeek-Session`、
  请求体的 `user`、提示词里的工作目录、User-Agent 依次决定（同 `server._session_key`）。
* `session reset` = 让该桶**下一轮开新网页会话**，并把客户端传来的完整历史**播种**进去。
  不删除客户端的对话历史，也不清除 DeepSeek 账户里的数据；只影响这一个桶。
  重置会解除该桶的会话绑定（重置的语义就是「开一条全新的网页会话」）。
* `session reseed` = 把「下一轮重发完整历史」写成**落盘的一次性标记**（`pending_reseed`）：
  进程重启、并发请求、失败重试都不会丢；真正发送成功后自动清除。
  它不是清除旧消息，而是**再次发送**上下文——那条会话里会出现重复内容。
* `session link <URL>` 默认认为目标会话**已有**此前上下文（只发增量）；
  目标会话其实是空的时用 `--seed`，下一轮会把完整历史播种进去。
  绑定后：页面丢失重建、空闲回收后重开、服务重启都会回到这条会话。
  轮转（上下文到顶 / 超出预算）会**解除**绑定，因为轮转必须开一条全新的网页会话。
  该桶正在生成回复时绑定不会当场换页（避免打断在飞的请求），而是在下一轮发送前生效。
* `session unlink` 只解除「钉在某条会话」的约束，**不动当前页面**：上下文不丢，
  当前页面仍停在原会话上。

## 4. 权限与安全

服务默认只监听 `127.0.0.1`，客户端 API Key 不构成真正的身份验证，因此：

* 聊天入口**不接** `RESET_TOKEN`（请求头在这一层拿不到），有副作用的命令靠清晰的执行
  回执和「只影响当前桶」的范围约束来控制风险；
* 回执里不打印 `.env` 值、登录 Cookie、令牌或其它桶的信息；内部异常只写日志，
  回复里只给稳定类型与短说明；
* 地址校验不为了「方便」而放宽，用户可控的 URL 不允许变成任意导航目标。

## 5. 与 ChatGPTBridge 版本的差异

| 差异 | 原因 |
| --- | --- |
| 没有 `/link`、`/unlink` 兼容别名 | 本项目原先没有这两个命令，统一走 `session link\|unlink` |
| 没有 `settings think` | DeepSeek 网页版没有可可靠读写的思考模式开关，不做无法验证的「成功」 |
| 没有 `/reset`、`/clear`、`/retry`、`/cancel`、跨桶列举、任意 shell / 写文件 | 与上游文档第 4 节一致：语义模糊或涉及任务取消 / 权限 / 会话隔离，不能只靠字符串分支保证正确 |

## 6. 测试

`tests/test_bridge_commands.py` 覆盖：精确匹配（多行 / 正文 / 代码块 / 历史命令不重放）、
参数与地址校验、帮助与注册表不漂移、只影响当前桶、浏览器未就绪时只读命令仍可用、
两条协议路径（chat 流式与非流式、Responses）行为一致、命令不写任务快照、
`reseed` 一次性标记的持久化与消费、`link` 的立即生效与桶忙时的延后对齐。
