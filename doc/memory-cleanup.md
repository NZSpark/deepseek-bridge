# 记忆清理与整合（Cleanup）

> 摘要：记忆会膨胀。本文规定什么时候清理、清什么、怎么保证不误删。
> 日常轻量清理在任务收尾时做；深度清理手动触发。**优先合并压缩归档，不直接删除。**

---

## 1. 三种触发

| 触发 | 时机 | 做什么 |
| --- | --- | --- |
| 日常轻量 | 每次任务收尾 | 覆盖 `state.md`；新决策/新坑追加到对应文件；顺手删掉刚失效的条目 |
| 周期性深度 | 手动，或 `state.md` 超过 60 行 / `decisions.md` 超过 400 行 | 去重、合并、归档、修索引 |
| 上下文超预算 | `harness.py check` 报 WARN | 压缩该文件，或把细节移入 `archive/` 并在原处留一行指针 |

---

## 2. 七项检查

### 2.1 过时检测（Stale）

**判据**：条目里的事实已与代码/现实不符。
**做法**：改写到正确，或标注 `[已过时 YYYY-MM-DD]` 后移入 `archive/`。
**不删**——历史能解释「为什么当时那样做」。

### 2.2 去重（Deduplication）

**判据**：同一事实在两个文件里都有正文（不是引用）。
**做法**：保留一处为正文，另一处改成路径引用。
**常见位置**：`project.md` 与 `README.md`、`lessons.md` 与 `doc/update.md`。

### 2.3 整合（Consolidation）

**判据**：`lessons.md` 里有 3 条以上讲同一类问题（如都是「等待/超时」）。
**做法**：合并成一条带子条目的经验，保留各自的判据。**原始编号保留**以便引用。

### 2.4 归档（Archiving）

**移入 `archive/` 的条件**（满足任一）：
- 决策已被新决策取代（标 `[已废弃 by Dxx]`）
- 经验对应的代码路径已删除
- 内容只在考古时有价值

**做法**：移到 `doc/memory/archive/<原名>-<YYYYMMDD>.md`，原处留一行指针。

### 2.5 冲突检查（Conflict）

**判据**：两条规则/决策互相矛盾（例：一处说默认串行，另一处说默认并行）。
**做法**：
- 能确定新旧的 → 旧条标 `[已废弃 by Dxx]`，新条写清取代关系
- **不能确定的 → 不改，列进本文件 §4「待人工确认」**

### 2.6 核心约束精简（Critical Pruning）

`AGENTS.md` §1 硬规则**不得超过 8 条**。新增前先问：能不能并进现有某条？
超了说明规则在膨胀——合并同类项，或把细节下沉到 `lessons.md`。

### 2.7 状态压缩（State Compaction）

`state.md` 只保留：**正在进行 / 最近完成（≤5 条）/ 阻塞 / 下一步（≤3 条）/ 基线命令**。
「最近完成」超过 5 条时，最旧的移到 `decisions.md`（若是决策）或删除（若只是流水账）。

---

## 3. 执行纪律

1. **优先合并压缩归档，不直接删除。**
2. **历史关键决策保留可追溯记录**——新决策不能静默覆盖旧决策。
3. **涉及核心规则或存在歧义，不得未经确认做不可逆修改。**
4. **记录变更摘要**：在 `archive/` 里留一份 `<日期>-cleanup.md`，写清移动了什么、为什么。
5. **清理后重跑** `python3 scripts/harness.py check`，确认索引不断链。
6. **不要为 cleanup 增加复杂机制**——本节就是全部，不需要额外工具。
