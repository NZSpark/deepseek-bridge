# 决策记录（ADR 式，只追加）

> 摘要：每条含「背景 / 决定 / 理由 / 被否方案」。新决策追加在末尾，不修改旧条目；
> 被推翻的决策标 [已废弃 by Dxx]，保留原文以留痕。

## D01 · 浏览器桥接而非复刻私有接口

- 决定：用 Playwright 驱动真实 Chromium 页面，不逆向 chat.deepseek.com 的 HTTP 接口。
- 理由：风控对真人浏览器最宽容、登录权益自动继承、失败可观察（DOM 状态）。
- 被否：复刻私有接口——要复刻签名/风控，一次改版全废，且失败难以解释。

## D02 · 会话按任务分桶

- 决定：X-DeepSeek-Session / user 显式优先；缺失时按提示词里的工作目录分桶，再按 User-Agent。
- 理由：两个 Pi 在不同目录跑各自会话，无需配置；分桶隔离上下文，避免串线。
- 注意：分桶只隔离上下文，不是并发。真并发要按桶加锁且有风控风险，默认串行。

## D03 · 结束判定用多信号与门

- 决定：停止控件消失 + 生成标记为假 + 内容静默窗口，三者与门；不用固定 sleep，不用节点数量。
- 理由：单一信号都会误判（旧内容残留、DOM 延迟、流式抖动）。
- 配套：阈值一律用「秒」，不用「轮询次数」——调快轮询会等比削弱停滞保护。

## D04 · 坏 tool_call 自动重发

- 决定：声明了 tools 但回复里的 tool_call 结构坏（空围栏/截断/JSON 语法错/裸标记），在同一会话补提示词重发，默认 2 次（MALFORMED_RETRIES）。
- 理由：把畸形调用透传给客户端会直接失败；重发成本低于让客户端重试整轮。
- 被否：直接返回坏文本——客户端解析崩溃，错误信息也无法定位。
- 详见：doc/toolcall_retry.md。

## D05 · DSML 声称但救不出才判坏

- 决定：DSML_CLAIM 只认 <…DSML… calls/invoke> 标签；先问解析层能否救出，救不出且有标签才判坏。
- 理由：DSML 是模型退回原生 DSL 的合法表达，无条件判坏会与解析层打架；完全不看 DSML 则会漏掉空壳。
- 注意：块是否闭合不构成判据，只看解析结果——闭合块内夹裸换行照样判坏。

## D06 · 流式重发先缓冲

- 决定：工具模式下 on_delta=None 先缓冲，判定通过才吐给客户端。
- 理由：否则客户端会看到「坏内容 + 重发内容」两段，前端无法处理。
- 代价：首字延迟增加，工具调用场景可接受。

## D07 · skill 与同族共享源解除关联（v1.4.0）

- 决定：删除 family.json / family_sync.py / test_family_sync.py / family-source 版本钉，skills/web-to-openai-api/ 自成一体。
- 理由：跨仓库同步从未真正发生，机制只剩维护成本 + sync 误覆盖风险。
- 配套：门禁 R5 从「钉新鲜」改为「skill 必须真正自包含」（残留即 FAIL）。
- 保留：正文「同族实测」标注作为知识来源保留，不代表维护关系。

## D08 · harness 单一事实源 + 四层记忆

- 决定：规则只写 AGENTS.md；CLAUDE.md / .codex/instructions.md 各 3 行指针。记忆按变化频率分四层。
- 理由：三套规则各写一份必然漂移冲突；按频率分层让稳定知识不被高频状态污染。
- 被否：每工具维护独立知识库——重复、必然不同步。

## D09 · 背景进程启动必须 setsid + 重定向三件套

- 决定：scripts/start_all_bridges.sh 用 setsid cmd </dev/null >>log 2>&1 &，等待循环用递减计数器。
- 理由：( cd … && nohup … & echo $! ) 会让父 shell 等子进程而卡死；$SECONDS 进子 shell 会重置导致循环不收敛。
- 实证：初版实测死循环，改后 start/stop 均正常返回。
